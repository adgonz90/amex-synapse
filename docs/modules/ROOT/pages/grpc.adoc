= gRPC

`synapse-api-grpc` exposes operations as gRPC services on Spring Boot's gRPC server. You bind the methods of a
service generated by `protoc` in a `GrpcBindings` bean; Synapse compiles it into a service that Boot serves, maps each
request message to the operation's input record, calls the operation through the pipeline and maps its output to the
response message. Errors are gRPC statuses with `google.rpc` error details.

[source,xml]
----
<dependency>
  <groupId>io.americanexpress.synapse</groupId>
  <artifactId>synapse-api-grpc</artifactId>
</dependency>
----

The module brings Boot's gRPC server module (`spring-boot-grpc-server`, not the starter, which would add a logging
backend), `grpc-netty`, `grpc-services` (reflection and health), `grpc-protobuf` and `grpc-stub`. The service module
also generates its messages and stubs from its `.proto` files, for example with the `protobuf-maven-plugin` that
`spring-boot-starter-parent` configures.

* *Transport.* Boot runs a Netty server on `spring.grpc.server.port` (9090 by default), next to the web server if
  there is one. To use shaded Netty, exclude `io.grpc:grpc-netty` from `synapse-api-grpc` and add
  `io.grpc:grpc-netty-shaded`, as Boot documents.
* *Servlet transport.* gRPC served by the servlet container (a `GrpcServletRegistration` bean) is not supported
  together with `synapse-api-rest`: the REST edge filters would apply to gRPC calls. Startup fails with
  `gRPC served by the servlet container is not supported together with synapse-api-rest yet: the REST edge would filter
  gRPC calls.` (action: `Use the default Netty transport (keep io.grpc:grpc-netty), or remove synapse-api-rest.`).

The plugin is active when Spring gRPC and grpc-java are on the class path and `spring.grpc.server.enabled` is not
`false`. Boot starts its server only when at least one service bean exists. As with every operation, tracing must be
present (see xref:core.adoc#tracing[Tracing is required]). An operation bean and a `GrpcBindings` bean are all the
configuration a method needs.

NOTE: Not available yet: `PageQuery` and `PageResult` over gRPC (page tokens come in plan 3b), streaming methods,
input components bound from request metadata, and gRPC clients (P2).

The sample `samples/rest-books` in the repository serves the same operations over REST and gRPC; its
https://github.com/americanexpress/synapse/blob/main/samples/rest-books/README.md#grpc[README] calls them with
`grpcurl`.

== Bindings

[source,java]
----
@Bean
GrpcBindings bookService(GetBookOperation getBook, CreateBookOperation createBook) {
    return GrpcBindings.service(BookServiceGrpc.getServiceDescriptor())
        .unary(BookServiceGrpc.getGetBookMethod(), getBook).notFound(BookErrors.BOOK_NOT_FOUND)
        .unary(BookServiceGrpc.getCreateBookMethod(), createBook)
            .context(CreateBookRequest::channel, context -> context.attribute("channel").orElse(null))
        .bindAllByName()
        .build();
}
----

* One `GrpcBindings` bean binds one service. Declare one bean per service.
* `.unary(method, operation)` binds a method, given by its generated descriptor, to an operation bean. Only
  `QueryOperation` and `CommandOperation` beans can be bound; a `BusinessOperation` does not compile.
* `.bindAllByName()` binds each method that no `.unary` call binds to the operation named after it: `GetBook` to
  `get-book`, `GetHTTPStatus` to `get-http-status` (see xref:core.adoc#_contracts_and_naming[Contracts and naming]).
* Per method: `.map("field.path", Record::component)` binds a component to another field, `.context(Record::component,
  ctx -> ...)` sets an input component from the request context instead of a field, and `.notFound(code)` sets the
  error of an empty `Optional` (see <<not-found>>).

Components are referenced by method reference, never by string, so renaming a record component breaks the
compilation of the binding, not startup. Bindings belong in the service module's `api.grpc` package. The bean is a
`BindableService`, so Boot's server serves it like a hand-written service and applies the same interceptors.

Building the bindings only records them. They are checked and compiled when the bean is created, so the bean must be
declared with `@Bean`: a `GrpcBindings` that Synapse never compiled throws
`GrpcBindings for <service> was not compiled: declare it as a @Bean so synapse-api-grpc can bind it` when the server
asks for it. Every method of the service must be bound, so a service with a streaming method is written by hand (see
<<escape-hatch>>).

The operation must be the Synapse bean, so that its calls run through the pipeline (validation, deadline,
observation, translation and failure logging).

[#startup-failures]
=== Startup failures

A binding problem fails startup with a `SynapseConfigurationException` whose description starts with the method and
the operation, `gRPC method <service>/<method> (<operation>): `, followed by the problem:

[cols="3,3",options="header"]
|===
|Problem |Action
|`no operation is bound`
|`Bind it with .unary(...), or add .bindAllByName() and an operation named <operation-name>.`
|`more than one operation is named <name> (<classes>)` (with `.bindAllByName()`)
|`Give the operations different names with @OperationName, or bind the method with .unary(...).`
|`bound more than once` |`Bind each method once.`
|`is <type>; only unary methods can be bound in Synapse 2.0` |`Implement it in a hand-written *ImplBase service.`
|`belongs to <other service>, not to <service>`
|`Use the method descriptors of the service the bindings were created for.`
|`the request marshaller is not a protobuf message marshaller` (or `response`)
|`Bind the methods of a service generated by protoc with grpc-java's plugin.`
|`<record>.<component> can't be mapped to <message>.<field> (<field type>)`
|`Change the component type, or map another field with .map(...).`
|`<record>.<component> is @Nullable but <message>.<field> has no presence`
|`Use a wrapper type or proto3 optional for the field, or make the component non-null.`
|`<record>.<component> has no source`
|`Add the field to <message>, map one with .map(...), or set it with .context(...).`
|`<record>.<component> has no field in <message>` |`Add the field to the message, or map it with .map(...).`
|`<message>.<field> is part of oneof <oneof>` |`Map it explicitly with .map("<field>", ...).`
|`<type> is not supported over gRPC yet; gRPC page tokens come in plan 3b`
|`Expose this operation over REST until then.`
|`<type> is a persistence entity`
|`Bind a record from the service's model and map the entity in the operation.`
|===

Startup also fails, with the method named, when:

* the input type is not a record or `Void`, or the output is not a record, an `Optional` or `List` of one, or `Void`;
* the input or output is nested more than 32 levels deep or holds more than 10,000 types;
* a `.map` component is in neither the input nor the output record (or a record nested in one), a `.map` path names
  no field, or a `.context` component is not in the input;
* a component has two sources (`.map` and `.context`, or two of either);
* `.notFound` is declared on a method whose output is not an `Optional`;
* two output components write the same field (or one writes inside the other's message), or write two members of one
  `oneof`;
* a Java enum constant has no protobuf value, or matches the enum's unspecified value (see <<mapping>>).

[#mapping]
== Message mapping

Synapse reads the request and writes the response as `DynamicMessage`s over the generated descriptors; it never
instantiates the generated message classes. A component maps to the field whose JSON name equals the component name
(`published_on` and `publishedOn`). `.map("author.name", Record::component)` names another field: the path is
relative to the message of the component's own record, dotted to reach a field of a nested message.

[cols="2,3",options="header"]
|===
|Proto field |Record component
|`string` |`String`, or any type Boot's `ApplicationConversionService` converts both ways (`UUID`, `BigDecimal`,
`LocalDate`). `java.time` values are read and written in ISO only, whatever the locale.
|`int32`, `sint32`, `sfixed32`, `uint32`, `fixed32` |`int`/`Integer` or `long`/`Long`
|`int64`, `sint64`, `sfixed64`, `uint64`, `fixed64` |`long`/`Long`
|`bool`, `double`, `float` |Their Java types
|`bytes` |`byte[]`
|`google.protobuf.Timestamp` |`Instant`, from 0001-01-01T00:00:00Z to 9999-12-31T23:59:59.999999999Z
|`google.protobuf.Duration` |`java.time.Duration`
|The nine wrapper types (`Int32Value`, `StringValue`, ...) |A component of the wrapped type, usually `@Nullable`
|An enum |A Java enum (see below)
|Another message |A record
|`repeated T` |`List<T>`
|`map<K, V>` |`Map<K, V>`
|===

Enums match by name: a value matches the constant of the same name, or the constant named by the rest of the value
after the enum's prefix, as the protobuf style guide names values (`GENRE_FICTION` in `enum Genre` is
`Genre.FICTION`). A zero value named `*_UNSPECIFIED` or `*_UNKNOWN` is `null`. Every Java constant needs a value.

*Presence.* A `@Nullable` component needs a field with presence: a message, a wrapper, a proto3 `optional` field, a
`oneof` member, or an enum whose zero value is unspecified. Otherwise "absent" would silently become `0` or `""`, and
startup fails. A field without presence always has a value (its default), so a non-null component bound to one is
never missing.

*`oneof`.* A `oneof` member is mapped only with an explicit `.map`. The synthetic `oneof` of a proto3 `optional` field
doesn't count.

*Shapes.*

* A `Void` input takes `google.protobuf.Empty` or any message without fields.
* A `Void` output, or a `null` one, writes the empty response message.
* An `Optional<T>` output writes its value; an empty one is the method's not-found error (see <<not-found>>).
* A `List<T>` output writes the response message's only field, which must be `repeated`.

*Input.* Request fields without a component are ignored. Every input component needs a field or a `.context`. Problems
are collected, in component order, into one `VALIDATION_FAILED` (`INVALID_ARGUMENT`) with a violation per field, at
most 50:

[cols="3,2",options="header"]
|===
|Problem |Violation message
|A value that can't be converted (an id that isn't a UUID, an unknown enum number, a date that isn't ISO, an unsigned
value too large for the component) |`is not a valid value`
|A non-null component whose field is absent (a message, wrapper or `optional` field not set, an unspecified enum)
|`must not be null`
|===

The violation `field` is the proto field path from the request (`author.country_code`, `tags[2]`); in a map, it is
the map field's path, because the key is the caller's data. A component set by `.context` is named by its component
name. Violations never repeat the rejected value. The record is built with its canonical constructor once every field
is read. A constructor that throws is `VALIDATION_FAILED` without violations for the request's own record, and
`{field, is not a valid value}` for a nested record (the exception is logged at DEBUG); a `SynapseException` it throws
reaches the caller unchanged. Jakarta Validation then runs in the pipeline, and its violations are named by the proto
field path too (`published_on`), or by the component path when the binding maps no field to it. Inside a list the
names are the proto ones and the index is kept (`authors[0].country_code`). Inside a map the key is left out, as the
request's own violations leave it out (`authors_by_rank.country_code`), so a field has one name and the caller's key
is never echoed. A path that names a list or map element but can't be read against the binding is cut before its
first bracket.

*Output.* Every output component needs a field; response fields without a component stay unset, and a `null`
component leaves its field unset. A value that can't be written (outside its field's range, or a `null` list element)
fails the call with `INTERNAL`.

[#errors]
== Errors

A failed call is a status code, a description, and a `google.rpc.Status` with error details (AIP-193) in the
`grpc-status-details-bin` trailer. With `synapse.errors.include-detail` on, a missing book of the sample reads:

----
Code: NOT_FOUND
Message: The resource was not found
google.rpc.Status: {
  "code": 5,
  "message": "The resource was not found",
  "details": [{
    "@type": "type.googleapis.com/google.rpc.ErrorInfo",
    "reason": "BOOK_NOT_FOUND",
    "domain": "rest-books",
    "metadata": {
      "correlationId": "demo-123"
    }
  }]
}
----

The details are, in this order:

* `ErrorInfo`, always: `reason` is the error code, `domain` is `spring.application.name` (or `synapse` when it is not
  set), and `metadata.correlationId` is the correlation id.
* `BadRequest`, when the error has violations: one `FieldViolation` per violation (see <<mapping>>). It keeps the
  first violations that fit in about 3 KiB, whole ones only, so that the trailer stays within a client's default
  8 KiB metadata limit.
* `RetryInfo`, when the call was rejected by the concurrency limit: `retry_delay` 1 s.

The description is the formatted message, in the caller's `accept-language` locale, only when
`synapse.errors.include-detail` is `true` (default `false`, in every environment; see xref:core.adoc#errors[Errors]).
Otherwise it is empty. Stack traces, exception class names and internal messages never appear.

The status comes from the error's category:

[cols="2,2",options="header"]
|===
|Category |Status
|`INVALID_INPUT` |`INVALID_ARGUMENT`
|`UNAUTHENTICATED` |`UNAUTHENTICATED`
|`FORBIDDEN` |`PERMISSION_DENIED`
|`NOT_FOUND` |`NOT_FOUND`
|`CONFLICT` |`ABORTED` (the code `ALREADY_EXISTS`: `ALREADY_EXISTS`)
|`PRECONDITION_FAILED` |`FAILED_PRECONDITION`
|`RATE_LIMITED` |`RESOURCE_EXHAUSTED`
|`UNAVAILABLE` |`UNAVAILABLE`
|`TIMEOUT` |`DEADLINE_EXCEEDED`
|`INTERNAL` |`INTERNAL`
|===

Core's `STALE_VERSION` is therefore `ABORTED`. There is no `If-Match` over gRPC: a version is a field of the request.

Override the status of any code, for every operation or for one, with the code in brackets and a `Status.Code` name:

[source,properties]
----
synapse.api.grpc.errors.status.[BOOK_NOT_FOUND]=FAILED_PRECONDITION
synapse.api.grpc.operations.get-book.errors.status.[BOOK_NOT_FOUND]=OUT_OF_RANGE
----

The first that applies wins: the operation's override, the global override, the fixed status of a built-in code
(`ALREADY_EXISTS`, and `METHOD_NOT_FOUND`), the category's status. An override of `OK` fails startup with
`<key>.[<code>] is OK, which is not an error status.`

[#not-found]
=== Not found

An empty `Optional` output (or `null` for an `Optional` output) is `NOT_FOUND` with the code `NOT_FOUND`, or the code
given to `.notFound(code)`. Over gRPC the error gets no message arguments, because a request has no path variables to
fill them from (REST fills `+{0}+` from the route's path variables; see xref:rest.adoc#responses[REST responses]):

* When the declared code's template has placeholders (`+Book {0} was not found+`), or is not a valid `MessageFormat`
  pattern, the description is `NOT_FOUND`'s message (`The resource was not found`, or its localized `MessageSource`
  entry) instead of the template unfilled. The reason in `ErrorInfo`, and the status with its overrides, stay those of
  the declared code.
* A template without placeholders keeps its own text.
* The decision is made on the template only. A `MessageSource` entry for the code takes the same arguments as the
  code's template: a template with placeholders whose localized entry has none still gets `NOT_FOUND`'s message, and a
  template without placeholders whose entry has some shows that entry as written.

To give a gRPC caller a specific message, give `.notFound` a code whose template has no placeholders, or throw the
`SynapseException` with its arguments from the operation.

=== Calls that never reach an operation

[cols="2,2,4",options="header"]
|===
|Case |Status |Details
|Request bytes that aren't a valid message |`INVALID_ARGUMENT` |`ErrorInfo` with `MALFORMED_REQUEST`, and the
correlation id.
|A method no service declares |`UNIMPLEMENTED` |`ErrorInfo` with `METHOD_NOT_FOUND` (`GrpcErrors`), and the correlation
id in the trailers and in `ErrorInfo`.
|A message over `spring.grpc.server.inbound.message.max-size` |`RESOURCE_EXHAUSTED` |None: grpc-java's own status.
|Metadata over `spring.grpc.server.inbound.metadata.max-size` |The client's own failure |None (see below).
|The concurrency limit reached |`UNAVAILABLE` |`ErrorInfo` with `UNAVAILABLE`, and `RetryInfo` of 1 s.
|===

* *Unknown methods* are answered by Synapse's fallback handler registry (the `ServerBuilderCustomizer` bean
  `synapseGrpcFallbackHandlers`). grpc-java runs a fallback method without the server's interceptors, so neither the
  edge nor tracing sees these calls: the registry accepts the caller's correlation id (validated as in
  xref:core.adoc#correlation-id[Correlation id]) or generates one itself, and never reads the request.
* *An oversized message* is rejected by grpc-java, which checks the size only once the call has asked for its message.
  The call therefore reaches the interceptors (`interceptCall`, then `onCancel`), but no message is delivered: the
  operation is not invoked, no exception handler runs, the call's concurrency permit is released, and Synapse logs
  nothing. The client gets `RESOURCE_EXHAUSTED` with grpc-java's description and no `ErrorInfo`.
* *Oversized metadata.* The server advertises its metadata limit in its HTTP/2 settings
  (`SETTINGS_MAX_HEADER_LIST_SIZE`, 16384 bytes by default), so a grpc-java client refuses to send larger metadata
  and fails the call itself, before the server sees it.

=== Exception handlers

Synapse's `GrpcExceptionHandler` (`synapseGrpcExceptionHandler`) is ordered last, so your handlers, `@GrpcAdvice`
classes and Spring Security's handler answer first; Spring gRPC uses the first answer. Synapse's handler always
answers:

* a `StatusException` or `StatusRuntimeException` passes through unchanged (an escape hatch's explicit choice); the
  edge still adds the correlation id to the trailers;
* a `SynapseException` is written as above;
* anything else is `INTERNAL`, logged once at ERROR with its stack trace on `io.americanexpress.synapse.api.grpc`, with
  the correlation id.

IMPORTANT: A `@GrpcAdvice` class and its `@GrpcExceptionHandler` methods must be `public`. Spring gRPC invokes them
without making them accessible; otherwise the call is answered `INTERNAL`, with no `ErrorInfo`.

Logging: failures of operations are logged by the pipeline (see xref:core.adoc#logging[Logging]). A call rejected
before an operation runs (a malformed request, binding violations, the concurrency limit, an unknown method) is
logged at DEBUG at most.

== Correlation id and context

The edge opens the Synapse `RequestContext` around every listener callback of a call, inside the span of Boot's
server observation, so the correlation id and attributes reach the MDC, the logs, `@Async` and virtual threads and
outbound calls. The context is closed on the callback's thread when the callback returns or throws, so no context or
MDC entry is left on a reused executor thread.

* *Correlation id:* read from the metadata key `synapse.correlation.header` in lower case (`x-correlation-id`), first
  value, then validated and generated as described in xref:core.adoc#correlation-id[Correlation id]. It is echoed in
  the response headers when they are sent, or in the trailers when the call ends without headers (as an error
  usually does), always as the resolved id. It also tags the server observation as `correlation.id`.
* *Context attributes:* each one maps a metadata key to an attribute name:
+
[source,properties]
----
synapse.api.grpc.context.metadata.tenant=x-tenant
synapse.api.grpc.context.metadata.channel=x-channel
----
+
Keys must be lower case, ASCII (not ending in `-bin`) and valid metadata keys; otherwise startup fails. Attributes are
read in this order, from the first value of the key, so when there are more than the context limits allow
(`synapse.context.inbound.max-entries`, `.max-size`), the last ones are dropped. An empty value counts as absent.
* *Locale:* from the first language range of `accept-language` (by weight), only when present.

Synapse adds `correlationId` and the attribute names to Boot's baggage remote fields and correlation (MDC) fields, as
for REST.

=== Baggage and trust

A trusted caller (the default, `synapse.context.inbound.trusted=true`) can also send the correlation id and the
attributes as W3C `baggage` entries named `correlationId` and after each attribute, or in metadata keys of those names
when they are remote fields. The edge removes these Synapse fields from `baggage` before tracing reads it; they are only
candidates, used when the mapped key is absent, and are validated like metadata values. Other baggage entries and
remote fields pass through.

A public-facing service sets `synapse.context.inbound.trusted=false`. Then the edge hides from Boot's observation
interceptor and everything after it:

* the trace keys, so each call starts a new trace: W3C Trace Context (`traceparent`, `tracestate`) and B3 (`b3`,
  `x-b3-traceid`, `x-b3-spanid`, `x-b3-parentspanid`, `x-b3-sampled`, `x-b3-flags`) only;
* `baggage` and the key of every remote baggage field (`management.tracing.baggage.remote-fields`);
* and core drops the inbound context attributes. The correlation metadata is still accepted.

WARNING: The masking works on the metadata that Boot's observation interceptor reads. A tracer that reads metadata
before the interceptors, such as a `ServerStreamTracer` (grpc-opentelemetry added with a `ServerBuilderCustomizer`),
is not covered by `trusted=false`. The same holds for the OpenTelemetry Java agent, which instruments grpc-java
itself: under the agent, `trusted=false` is not yet verified to restart the trace or drop the caller's baggage. Plan 5
checks and closes this gap.

Never base a security decision on an attribute or on baggage; callers control them.

== Deadlines

The call's gRPC deadline becomes the request deadline, capped by `synapse.api.grpc.deadline.max` (30s). A call
without a gRPC deadline gets `synapse.api.grpc.deadline.default` (10s), so every call has a deadline. The default must
be positive and not above the maximum; otherwise startup fails. The cap applies only to the request context: the
call's own gRPC deadline stays as the caller set it. The pipeline fails a call whose deadline has passed with
`DEADLINE_EXCEEDED` before `execute`; a running operation is not interrupted.

== Limits

[cols="2,1,4",options="header"]
|===
|Limit |Default |Property
|Inbound message |4 MB |Boot's `spring.grpc.server.inbound.message.max-size`
|Inbound metadata |16 KB |Boot's `spring.grpc.server.inbound.metadata.max-size`, which Synapse defaults to 16KB (Boot's
own default is 8 KB) at lowest precedence, so your value wins
|Concurrent calls |200 |`synapse.api.grpc.max-concurrent-calls` (at least 1)
|===

*Concurrency.* With virtual threads, the server's executor no longer limits how much work runs at once, so the edge
caps it. A call that finds the limit reached is closed at once with `UNAVAILABLE` and `RetryInfo` of 1 s, and nothing
behind Synapse's context interceptor runs; it never waits. Calls to `grpc.health.v1.Health` and both server
reflection services are never counted, so health checks are answered under full load.

A call holds its permit until it completes or is cancelled. grpc-java delivers the cancellation only after the
callback that runs the operation returns, so a cancelled call, or one whose deadline expired, holds its permit until
its handler returns. An operation that blocks should watch the call's gRPC `Context` cancellation or its
`RequestContext` deadline.

== Threads

When `spring.threads.virtual.enabled=true`, Synapse gives Boot's server a `GrpcServerExecutorProvider` that runs each
call on a new virtual thread named `grpc-<n>`. It is closed with the context, after the gRPC server has stopped: it
waits for calls still running for at most `spring.grpc.server.shutdown.grace-period`, then interrupts them. Define a
`GrpcServerExecutorProvider` bean to replace it.

[#edge-interceptors]
== Edge interceptors

The edge is two global server interceptors around Boot's. Replace one by defining a bean with its name.

[cols="2,1,4",options="header"]
|===
|Bean |Order |Does
|`synapseGrpcEdgeInterceptor` |`HIGHEST_PRECEDENCE` |Hides or strips propagation metadata before tracing reads it,
and echoes the correlation id.
|Boot's observation interceptor |`0` |The server observation and its span.
|Boot's exception handling interceptor |`1` |Asks the `GrpcExceptionHandler` beans for a failure's status.
|`synapseGrpcContextInterceptor` |`100` |Opens the request context (correlation id, attributes, locale, deadline)
and caps concurrent calls.
|===

The other beans (`grpcDeadlinePolicy`, `grpcConcurrencyLimit`, `grpcErrorStatuses`, `grpcStatusWriter`,
`synapseGrpcExceptionHandler`, `synapseGrpcServiceCompiler`, `synapseGrpcBindingsCompiler`,
`synapseGrpcExposureInventory`, the virtual-thread executor provider, the `synapseGrpcFallbackHandlers` customizer,
and the `synapseGrpcServletCheck` and `synapseGrpcReflectionAotCheck` startup checks) back off when you define your
own.

== Server reflection

Server reflection publishes the whole API to any caller, so it is off by default: Synapse sets Boot's
`spring.grpc.server.reflection.enabled` to `false` at lowest precedence, in every environment. An environment file
turns it on, for example for `grpcurl` in local runs (see xref:environments.adoc#safe-defaults[Safe defaults]):

[source,yaml]
----
# application-local.yaml
spring:
  grpc:
    server:
      reflection:
        enabled: true
----

The key decides whether Boot defines its reflection service bean, so under AOT it is fixed at build time. When the
application runs with AOT-generated artifacts and the value now differs from the one the build used, startup fails
with `spring.grpc.server.reflection.enabled is <now> but the AOT build used <then>: in a native image or AOT run it is
fixed at build time.` (action: `Set spring.grpc.server.reflection.enabled to <now> for the AOT build and build again,
or set it to <then> for this run.`). The value is read as Boot reads it: on when unset or `true`, off for any other
value. The check compares only when Boot could have defined the bean: `grpc-services` is on the class path and the
application has a service of its own.

== Health

Health checks are Boot's: its `grpc.health.v1.Health` service, configured under `spring.grpc.server.health.*`.
Synapse adds nothing to it, and never counts its calls against the concurrency limit.

[#shutdown]
== Shutdown

Boot's gRPC server stops first: its lifecycle has the highest phase, above Synapse's `INBOUND` and `DRAIN` phases. It
refuses new calls (`UNAVAILABLE`) and waits for the calls in flight for at most
`spring.grpc.server.shutdown.grace-period` (30s, Boot's default), then cancels the rest. Its stop is synchronous, so
this wait is not bounded by `spring.lifecycle.timeout-per-shutdown-phase`; count it as its own term in the Kubernetes
formula (see xref:core.adoc#shutdown[Shutdown]). Then the pipeline drains the operations still running.

== Exposure inventory

When the gRPC server starts, the plugin logs every method it binds, one INFO line each on
`io.americanexpress.synapse.api.grpc`:

----
Synapse gRPC exposes synapse.samples.books.v1.BookService/GetBook -> get-book on port 9090
----

A server without a port (in process) is reported as `in process`. Hand-written services are not listed.

[#escape-hatch]
== Escape hatch

A hand-written service (a `*ImplBase` subclass declared as a bean) that injects operations is the escape hatch for
what bindings can't express, streaming methods included. The operation call runs through the pipeline, and the
service gets the same edge: correlation id and context, deadline, concurrency limit and error details.

[source,java]
----
@Component
class WatchService extends WatchServiceGrpc.WatchServiceImplBase {

    private final GetBookOperation getBook;

    WatchService(GetBookOperation getBook) {
        this.getBook = getBook;
    }

    @Override
    public void watchBook(WatchBookRequest request, StreamObserver<BookEvent> events) {
        ...
    }
}
----

* An exception the service throws goes through the exception handlers above: a `SynapseException` gets the Synapse
  error details, a `StatusException` or `StatusRuntimeException` passes through, anything else is `INTERNAL`. So does
  an exception passed to `responseObserver.onError(...)`, except a status exception, which reaches the caller as it
  is, with the correlation id added. This holds when the service completes the call from a thread of its own (a
  future's callback, a streaming producer): the error details carry the call's correlation id and locale.
* The service maps messages itself; no field mapping, violation paths or not-found handling apply.

== Native image and AOT

The plugin registers lambda hints for the method references in bindings. Synapse reads a reference such as
`CreateBookRequest::channel` through its serialized form, which a native image allows only for lambda classes with
metadata. The hint is registered for the class that declares the `@Bean` method of each `GrpcBindings` bean, covering
every method reference created in that class. So:

* write the method references in the class that declares the `@Bean` method, not in a helper class it calls;
* declare the `@Bean` method's return type as `GrpcBindings`. A wider type (for example `BindableService`), or a
  `GrpcBindings` bean not created by a `@Bean` factory method, gets no lambda hints. In the same way, an operation bean
  declared with a wider type than its class (`ServiceOperation<?, ?>`) gets no hints for its input and output types,
  which core registers from the bean's declared type. The REST plugin has the same limitation.

The plugin needs no other hints: it never instantiates generated message classes, and the records it maps are the
operations' inputs and outputs, which core registers. Spring's AOT processing of a gRPC service is tested on the JVM.
A native image is not verified yet: `grpc-netty`, protobuf's runtime reflection on the descriptors, reflection on the
mapped records and enums, and the lambdas' `writeReplace` method. The native build of the reference application
(plan 5) checks them.

== Configuration

The gRPC properties are `synapse.api.grpc.*`; all are in the
xref:reference/configuration-properties.adoc[property reference]: `context.metadata.<attribute>`,
`deadline.default` and `.max`, `max-concurrent-calls`, `errors.status.[CODE]` and
`operations.<name>.errors.status.[CODE]`. The plugin also reads core's `synapse.correlation.*`,
`synapse.context.inbound.*` and `synapse.errors.*`, and sets defaults for two of Boot's `spring.grpc.server.*` keys
(`inbound.metadata.max-size`, `reflection.enabled`).
