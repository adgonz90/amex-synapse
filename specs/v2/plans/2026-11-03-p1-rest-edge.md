# P1 plan 2a of 5: REST edge, errors, bindings, limits — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `synapse-api-rest` up to a working plugin, plus `synapse-test-rest` and the plan-2 carry-overs that belong to the edge. The plugin covers:
- the inbound edge (correlation id, context attributes, deadline, inbound trust at the header level);
- RFC 9457 problem responses with Synapse's error mapping;
- `RestBindings`/`RestConventions` compiled to Spring MVC functional routes, with input binding and response mapping;
- request-size and concurrency limits;
- AOT hints.

`synapse-test-rest` provides `@SynapseRestTest`. Paging safety, conditional requests, API versioning, CORS and OpenAPI come in plan 2b.

**Architecture:** Three servlet filters form the edge, around Boot's `ServerHttpObservationFilter`:
1. A header-level propagation filter runs first. It hides or strips trace and baggage headers before tracing extracts them.
2. Boot's observation filter opens the server span.
3. A context filter runs inside that span and opens the Synapse scope with `ContextBinder`.

The concurrency and size limits follow the context filter. `RestBindings` beans compile into one `RouterFunction<ServerResponse>`. Each handler binds the input record (path, query, body, headers, cookies, context, custom), calls the proxied operation, so the plan-1 pipeline runs, and writes the response. A `HandlerExceptionResolver` and an `ErrorController` turn every failure into `application/problem+json`. Core gains a method-reference resolver, a W3C baggage header utility, and the outbound stripping primitive that P2 clients will use.

**Tech Stack:**
- Java 21 (`--release 21`, built on JDK 25).
- Spring Boot 4.1.2 modules: `spring-boot-webmvc`, `spring-boot-tomcat`, `spring-boot-http-converter`, `spring-boot-webmvc-test`, `spring-boot-resttestclient`.
- Spring Framework 7.0.10 (functional endpoints, `RestTestClient`).
- Micrometer Observation and Tracing with the OpenTelemetry bridge.
- Jackson 3.1.7 (`tools.jackson`), JUnit 5, AssertJ.

**Spec:** [specs/v2/BUILD.md](../BUILD.md) (§3, §5.3-5.5, §5.9, §6.1, §6.2, §12, §15 P1) and the reasons in [specs/v2/DESIGN.md](../DESIGN.md). The §4.1 rows dated 2026-11-03 for "P1 plan 2a" record this plan's maintainer decisions; see *Spec changes this plan records*.

## Global Constraints

**Branch, JDK and language**
- Branch: `feature/v2-p1-rest-edge` from local `main`. Never push. Merge to `main` locally only when the maintainer says so.
- JDK: run `export JAVA_HOME="$HOME/.jdks/jdk-25.0.5+8"; export PATH="$JAVA_HOME/bin:$PATH"` before any `./mvnw`. JDK 21 runs use `-Djvm="$HOME/.jdks/jdk-21.0.12.1+1/bin/java"`. Never a global `mvn`.
- Compile with `--release 21`: no Java 22+ APIs. Prefer records for data carriers.
- Every package has a `package-info.java` annotated `@NullMarked`; nullable types are `@Nullable` (JSpecify). Error Prone and NullAway must pass.
- Formatting: run the build; Spotless applies the profile locally. Don't hand-format. License header on every file.

**Auto-configuration and properties**
- Every feature is an `@AutoConfiguration` listed in `META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports`. Every bean is `@ConditionalOnMissingBean` (or a customizer).
- Every auto-configuration has `ApplicationContextRunner` (here `WebApplicationContextRunner`) tests: it activates, backs off to a user bean, binds its properties, and stays absent when its condition isn't met.
- Library jars depend on Boot **modules** (`spring-boot-<technology>`), never starters, except in test scope.
- Properties are typed `@ConfigurationProperties` records under `synapse.*` with Javadoc on every component. Never an alias for a Boot key. A different default for a Boot key is set only by an `EnvironmentPostProcessor` at lowest precedence.
- Map keys that contain characters other than letters, digits, `-` and `.` are written in brackets in docs, tests and examples: `synapse.api.rest.errors.status.[BOOK_NOT_FOUND]=423`.

**Library code**
- No remote I/O during bean creation. No `@ComponentScan`, no `@Import` of framework packages, no `@EnableWebMvc`, no `configureMessageConverters` replacement, no config files or `application.properties` in library jars.
- SLF4J API only in library code. Never expose stack traces, exception class names or internal messages to callers. Full detail and cause are logged server-side.
- No OpenTelemetry API in library code (DESIGN 4.1, *Micrometer and OpenTelemetry*). Trace and baggage handling at the REST edge works on HTTP headers and Micrometer's API only.
- Code outside `..internal..` packages is public API. Implementation classes go in `io.americanexpress.synapse.api.rest.internal.<feature>` and `io.americanexpress.synapse.core.internal.<feature>`.

**Tests**
- Unit tests are `*Test` (surefire); integration tests are `*IT` (failsafe). Each module tags at least one IT `@Tag("smoke")`.
- Per-module JaCoCo floor: 80% line / 70% branch. `-DskipTests` is never a passing build.
- Plugin error mapping is mutation-tested nightly (score ≥ 70%), so assert outcomes, not just "no exception".

**Dependencies and modules**
- Every new dependency version that Boot doesn't manage goes in the root `pom.xml` properties and `dependencyManagement`, and in `bom/synapse-bom`.
- New Synapse modules go in the root `<modules>`, the root `dependencyManagement` and `bom/synapse-bom`.
- Test libraries stay in test scope. The exceptions are `synapse-test` and the `synapse-test-<plugin>` artifacts, which set `synapse.enforcer.allowTestLibraries=true`.

**Commits and Boot version**
- Conventional Commits (`feat:`, `fix:`, `test:`, `build:`, `docs:`), each ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Spring Boot stays on 4.1.2. The 4.2.0 bump is a separate commit after reading the 4.2 release notes (DESIGN 4.1); it is not part of this plan.

**Spec values this plan implements**
- Correlation header `X-Correlation-Id` (`synapse.correlation.header`); ids are 1–128 characters of `[A-Za-z0-9._:-]`.
- Deadline header `Request-Timeout: <milliseconds>` (`synapse.api.rest.deadline.header`), default 10 s, max 30 s; malformed values are ignored.
- Request body limit 1 MB (`synapse.api.rest.max-request-size`; per route `.maxRequestSize(...)`). The header-size default `server.max-http-request-header-size=16KB` is set at lowest precedence.
- `synapse.api.rest.max-concurrent-requests=200`. Actuator management paths are never counted. When full: 503 `UNAVAILABLE` with `Retry-After: 1`.
- Context limits come from core: `synapse.context.inbound.max-entries=16`, `.max-size=4KB`, `.trusted=true`.

**Commands.**
- While iterating on a unit test: `./mvnw -q -pl api/synapse-api-rest -am test -Dtest=ClassName -Dsurefire.failIfNoSpecifiedTests=false`.
- While iterating on an IT: `./mvnw -q -pl api/synapse-api-rest -am verify -Dit.test=ClassNameIT -Dtest=NONE -Dsurefire.failIfNoSpecifiedTests=false`.

Neither counts as a passing build. Every task ends with `./mvnw -pl <module> -am verify` for each module it touched.

## Review Focus

1. **Raw caller baggage for Synapse fields.** `baggage: correlationId=evil` without an `X-Correlation-Id` header must give a valid id in MDC and on the span, never the raw value. With `trusted=false`, a caller's `traceparent` must not become the parent. Pinned in Task 6: `rawBaggageCorrelationIdNeverReachesMdc`, `untrustedRequestStartsANewTrace`.
2. **Context left on a thread after a failing request.** When the handler throws (or an error dispatch follows), the next request on that pooled or virtual thread must see no `RequestContext` and no `correlationId` in MDC. Pinned in Task 7: `contextIsClearedAfterFailingRequest`.
3. **Exception text in error bodies.** A malformed JSON body must yield 400 `MALFORMED_REQUEST` whose body contains no Jackson class name and no parser message, also outside production. Pinned in Task 5: `malformedJsonBodyHasNoExceptionText`.
4. **A required field left out of the JSON body.** A POST omitting a non-nullable component, including a primitive, must be 400 `VALIDATION_FAILED` with a violation for that field, not a `null`/`0` reaching the operation. Pinned in Task 9: `missingNonNullableComponentIsViolation`, `missingPrimitiveBodyPropertyIsViolation`.
5. **A concurrency permit lost when the handler throws or the request goes async.** After 200 failing requests, request 201 must still be admitted. Pinned in Task 11: `permitIsReleasedWhenTheHandlerThrows`, `permitIsReleasedOnAsyncCompletion`.
