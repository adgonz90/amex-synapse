> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `synapse-core` (BUILD.md §5.1–5.10), the core rows of `synapse-test` (§12) and `synapse-logging-log4j2`
(§5.8), so the REST, gRPC and data plans (P1 plans 2–4) can build on a tested pipeline and context model.

**Architecture:** Operations and business beans are Spring beans whose `execute` is intercepted by a Synapse AOP
advisor (CGLIB class proxies created by Boot's auto-proxy creator, ordered outside `@Transactional`). The advisor
runs the pipeline of §5.2. A single Synapse context value, propagated with Micrometer context-propagation, backs
`RequestContext`; the same scope opens tracing baggage for propagation and MDC. Everything is wired by
`@AutoConfiguration` classes with `ApplicationContextRunner` tests, and the pipeline also runs without Spring
(`SynapseOperations.invoke`) for unit tests.

**Tech Stack:** Java 21 (`--release 21`, built on JDK 25), Spring Boot 4.1.2 modules (`spring-boot-micrometer-*`,
`spring-boot-validation`, `spring-boot-jackson`), Micrometer Observation/Tracing with the OpenTelemetry bridge,
Jakarta Validation (Hibernate Validator 9.1), Jackson 3, ArchUnit 1.5.1, Log4j2 2.25, JUnit 5, AssertJ.

**Spec:** [specs/v2/BUILD.md](../BUILD.md) (§3, §4.3, §5, §12, §13, §14, §15 P1) and the reasons in
[specs/v2/DESIGN.md](../DESIGN.md) (§4.1 rows dated 2026-11-01 record this plan's maintainer decisions).

## Calls made in this plan (not in the spec; maintainers may change them)

| Call | Why |
|---|---|
| The pipeline is an infrastructure-role `Advisor` picked up by Boot's auto-proxy creator; operation and business bean definitions get `AutoProxyUtils.PRESERVE_TARGET_CLASS_ATTRIBUTE` so they are always CGLIB class proxies. | Bindings inject operations by concrete class (`GetBookOperation`); a JDK proxy would break that. Same mechanism as `@Transactional`, and Spring AOT pre-generates the proxy classes. |
| Advisor order `Ordered.HIGHEST_PRECEDENCE + 1000` (operations) and `+ 1001` (business). | Must sit outside the transaction advisor (default `LOWEST_PRECEDENCE`), per §5.2 step 5. |
| Startup fails (`SynapseConfigurationException` + a `FailureAnalyzer`) when an operation or business bean is final, is a record, a lambda or an anonymous class, has a final `execute`, implements both `QueryOperation` and `CommandOperation`, implements both `ServiceOperation` and `BusinessOperation`, isn't proxied (e.g. `spring.aop.auto=false`), has an invalid or duplicate name. | Each of these silently skips or confuses the pipeline. |
| "Outermost invocation" is per thread (a thread-local depth counter that is not propagated). An operation called from an `@Async` task counts as outermost on that thread. | The outer call may already have returned; the async failure must still be logged once. |
| `Error`s (`OutOfMemoryError`, `StackOverflowError`, …) are never translated; they propagate unchanged after the observation records them. | Translating them to `INTERNAL` would hide JVM failures. |
| Error-message arguments are converted with `String.valueOf` before `MessageFormat`, in the template and in `MessageSource` overrides alike. | `MessageFormat` would print `12345` as `12,345`; ids must print as given. |
| WARN logs for a replaced correlation id and for dropped context entries are rate-limited to one WARN per minute per kind; the rest go to DEBUG. | An attacker could otherwise flood logs by sending bad headers on every request (the burst limit is off by default). |
| Baggage field for the correlation id: `correlationId` (also the MDC key). Synapse merges `correlationId` and the attribute names bound under `synapse.api.rest.context.headers` and `synapse.api.grpc.context.metadata` into `management.tracing.baggage.remote-fields` and `management.tracing.baggage.correlation.fields` with an `EnvironmentPostProcessor` (union with the user's values). | Boot's OTel bridge reads these lists only from properties (checked in Boot 4.1.2 source, `OpenTelemetryTracingAutoConfiguration`). |
| `synapse.context.inbound.trusted=false` drops inbound attributes in core's binder; dropping inbound *baggage* and restarting the trace are done at each edge (REST/gRPC plans), because only the edge sees the raw request. | Core never sees protocol requests. |
| `PageQuery.size` is an `int` (the edge fills the default); the cursor/offset/size rules are checked in the pipeline's validation step and fail as `VALIDATION_FAILED`. | Keeps operation code free of nulls and keeps the rules in one place for every protocol. |
| `SpringDataPages.pageable(PageQuery)` returns an offset-based `Pageable` (any offset, not only multiples of size); cursor queries throw `IllegalArgumentException`. | `PageRequest` only supports page numbers; `offset=5&size=20` must not become a 500. |
| `LAST_FOUR` masks every character when the value has 4 or fewer characters (v1 revealed short values entirely). Masking counts code points, not `char`s. | Never reveal a short secret; never split a surrogate pair. |
| `@Masked` on a non-scalar value (object, collection, map, array) writes `"***"`. | Fail-safe: never leak what can't be masked character by character. |
| Unknown keys under `synapse.operations.<name>` log one WARN at startup listing them. | Typos in per-operation settings otherwise do nothing silently. |
| `synapse-logging-log4j2` fails startup with a clear message when Logback is also on the classpath. | Boot would pick Logback and silently ignore Log4j2; consumers must exclude `spring-boot-starter-logging` (documented; the parent may automate it in plan 5). |
| Lifecycle phases (`SynapseLifecyclePhases`): `INBOUND = DEFAULT_PHASE - 2048` (Boot's web server stop phase), `DRAIN = DEFAULT_PHASE - 4096`, `PUBLISHERS = DEFAULT_PHASE - 8192`, `CLIENTS = DEFAULT_PHASE - 9216`, `DATA_STORES = DEFAULT_PHASE - 10240`. | Stop runs from high to low phase: inbound → drain → publishers → clients → stores (§5.9); stores start first (§3.3). |
| `@SynapseOperationTest` registers a `MutableClock` fixed at `2026-01-01T00:00:00Z` unless the test defines a `Clock`, and includes Boot's OpenTelemetry tracing auto-configuration (no exporters) so the tracing check passes. | Boot's `@AutoConfigureTracing` in slices gives `Tracer.NOOP`, which the tracing check rejects. |

## Review Focus

1. **An operation bean the proxy can't wrap** (a `final` class, a record, a lambda `@Bean`, a `final execute`, or
   `spring.aop.auto=false`): a person expects a startup failure naming the bean, not an operation that silently runs
   without validation, translation or logging. Pinned in Task 8.
2. **Layer rules matching Synapse's own packages:** `..operation..` also matches `io.americanexpress.synapse.core.operation`,
   so a business bean implementing `BusinessOperation` or a contract model under `..contract.model..` must not be
   flagged. Pinned in Task 13.
3. **Error templates with apostrophes and numbers:** `"Can''t find book {0}"` with `12345` must read `Can't find book 12345`;
   a malformed template must not throw from `getMessage()`. Pinned in Task 2.
4. **Nested and failing invocations:** a nested failure is logged exactly once (outermost), keeps its code when it
   passes through the outer operation, and an `Error` is never turned into `INTERNAL`. Pinned in Task 7.
5. **Context leaking on pooled threads:** after a scope closes (including when the body throws), the thread has no
   context and no baggage, so the next request on that thread can't see the previous correlation id. Pinned in Task 3.

  - `NO_SYNAPSE_INTERNALS`: no class outside `io.americanexpress.synapse..` depends on `io.americanexpress.synapse..internal..`.
  - `NULL_MARKED_MODELS`: every class in `..operation..`, `..model..`, `..business..`, `..contract..` (generated
