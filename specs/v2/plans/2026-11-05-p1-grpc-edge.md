# P1 plan 3: gRPC edge, errors, bindings, test slice and sample — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `synapse-api-grpc` on Boot 4.1.2's own gRPC server support, plus `synapse-test-grpc` (`@SynapseGrpcTest`) and gRPC in `samples/rest-books`. The plugin covers:
- the inbound edge: metadata hiding for untrusted callers, correlation id, context attributes, locale, deadline, the concurrency limit;
- error mapping into Boot's gRPC exception handling, with `google.rpc.ErrorInfo`, `BadRequest` and `RetryInfo`;
- `GrpcBindings` (one service per bean, itself a `BindableService`) with descriptor-based record mapping and startup checks;
- protocol-only failures, AOT hints, and the two plan-3 carry-overs (REST strips gRPC attribute baggage; reflection off by default).

gRPC page tokens are not in this plan (proposed plan 3b, see *Defaults* #18).

**Architecture:** Boot creates and runs the server: `GrpcServerAutoConfiguration` discovers `BindableService` beans, applies the `@GlobalServerInterceptor` beans in `@Order` order with `ServerInterceptors.interceptForward`, and runs `GrpcServerLifecycle`. Synapse contributes only beans Boot consumes:
1. `SynapseGrpcEdgeInterceptor` (global, highest precedence): hides or strips trace and baggage metadata before Boot's observation interceptor (`@Order(0)`) extracts it, attaches a `GrpcCallState` to the `io.grpc.Context`, and echoes the correlation id on the response.
2. Boot's `ObservationGrpcServerInterceptor` (`@Order(0)`) and `GrpcExceptionHandlerInterceptor` (order 1).
3. `SynapseGrpcContextInterceptor` (global, `@Order(100)`): resolves the correlation id with core's `ContextBinder`, opens the Synapse scope around every listener callback, enforces the concurrency limit.
4. `SynapseGrpcExceptionHandler` (a `GrpcExceptionHandler`, ordered last) writes every failure as a gRPC status with error details.
5. Each `GrpcBindings` bean is compiled by a `BeanPostProcessor` into a `ServerServiceDefinition` over a copy of the generated service descriptor whose marshallers keep the request as raw bytes and write a `DynamicMessage`. Synapse's unary handler parses, maps to the input record, calls the proxied operation (so the plan-1 pipeline runs) and maps the output back.

## Global Constraints

**Branch, JDK and language**
- Branch: `feature/v2-p1-grpc-edge` from local `main` at 208065f2 (the spec and plan commit is its first commit). **Never push.** Merge to `main` locally only when the maintainer says so (squash, as for the earlier plans).
- JDK: run `export JAVA_HOME="$HOME/.jdks/jdk-25.0.5+8"; export PATH="$JAVA_HOME/bin:$PATH"` before any `./mvnw`. JDK 21 runs use `-Djvm="$HOME/.jdks/jdk-21.0.12.1+1/bin/java"`. Never a global `mvn`.
- Compile with `--release 21`: no Java 22+ APIs. Prefer records for data carriers.
- Every hand-written package has a `package-info.java` annotated `@NullMarked`; nullable types are `@Nullable` (JSpecify). Error Prone and NullAway must pass. A test package with the same name as a main package has no `package-info.java` of its own. Packages generated by `protoc` have none (NullAway's `OnlyNullMarked` skips them; `SynapseArchitecture` already exempts proto-generated classes).
- Formatting: run the build; Spotless applies the profile locally. Don't hand-format. License header on every hand-written file, `.proto` files included if Spotless checks them (follow what the build does).
- Don't edit `.vscode/` or a pom while a Maven build runs (VS Code shares `target/`).

**Auto-configuration and properties**
- Every feature is an `@AutoConfiguration` listed in `META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports`. Every bean is `@ConditionalOnMissingBean` (by type, or by name for interceptor and customizer beans).
- Every auto-configuration has `ApplicationContextRunner` tests: it activates, backs off to a user bean, binds its properties, and stays absent when its condition isn't met.
- Library jars depend on Boot **modules**, never starters, except in test scope.
- Properties are typed `@ConfigurationProperties` records under `synapse.*` with Javadoc on every component. Never an alias for a Boot key. A different default for a Boot key is set only by an `EnvironmentPostProcessor` at lowest precedence.
- Map keys that contain characters other than letters, digits, `-` and `.` are written in brackets in docs, tests and examples: `synapse.api.grpc.errors.status.[BOOK_NOT_FOUND]=FAILED_PRECONDITION`.
- Never define Boot's gRPC beans (`GrpcServiceDiscoverer`, `GrpcServiceConfigurer`, server factories, `GrpcServerLifecycle`, `GrpcExceptionHandlerInterceptor`, `ObservationGrpcServerInterceptor`). Synapse adds `BindableService`, `GrpcExceptionHandler`, `@GlobalServerInterceptor`, `ServerBuilderCustomizer` and `GrpcServerExecutorProvider` beans, which Boot consumes.

**Library code**
- No remote I/O during bean creation. No `@ComponentScan`, no `@Import` of framework packages, no config files or `application.properties` in library jars.
- SLF4J API only in library code. Never expose stack traces, exception class names or internal messages to callers; full detail and cause are logged server-side.
- No OpenTelemetry API in library code. Trace and baggage handling at the gRPC edge works on `io.grpc.Metadata` and Micrometer's API only.
- Code outside `..internal..` packages is public API. Implementation classes go in `io.americanexpress.synapse.api.grpc.internal.<feature>` and `io.americanexpress.synapse.core.internal.<feature>`.

**Tests**
- Unit tests are `*Test` (surefire); integration tests are `*IT` (failsafe). Each module with ITs tags at least one fast IT `@Tag("smoke")`.
- Every Spring Boot test runs as `test`; every module whose tests start a context has `src/test/resources/application-test.yaml` (it may be comment-only).
- Per-module JaCoCo floor: 80% line / 70% branch; 90% of changed lines covered. `-DskipTests` is never a passing build.
- Plugin error mapping is mutation-tested nightly (score ≥ 70%), so assert outcomes (status code, `ErrorInfo.reason`, metadata), not just "no exception".
- ITs that need a real transport use Netty on `spring.grpc.server.port=0` and `@LocalGrpcServerPort` (`org.springframework.boot.grpc.test.autoconfigure.LocalGrpcServerPort`); slice tests use Boot's in-process transport.

**Dependencies and modules**

- New Synapse modules go in the root `<modules>`, the root `dependencyManagement` and `bom/synapse-bom`.
- Test libraries stay in test scope; `synapse-test-grpc` sets `synapse.enforcer.allowTestLibraries=true`.

| Streaming | `... : is <type>; only unary methods can be bound in Synapse 2.0` | `Implement it in a hand-written *ImplBase service.` |
| Wrong service | `... : belongs to <other service>, not to <service>` | `Use the method descriptors of the service the bindings were created for.` |
| Unmappable | `... : <record>.<component> can't be mapped to <message>.<field> (<field type>)` | `Change the component type, or map another field with .map(...).` |
| Nullable without presence | `... : <record>.<component> is @Nullable but <message>.<field> has no presence` | `Use a wrapper type or proto3 optional for the field, or make the component non-null.` |
| No source | `... : <record>.<component> has no source` | `Add the field to <message>, map one with .map(...), or set it with .context(...).` |
| No field for output | `... : <record>.<component> has no field in <message>` | `Add the field to the message, or map it with .map(...).` |
| Oneof | `... : <message>.<field> is part of oneof <oneof>` | `Map it explicitly with .map("<field>", ...).` |
| Paging | `... : <type> is not supported over gRPC yet; gRPC page tokens come in plan 3b` | `Expose this operation over REST until then.` |
| Entity | `... : <type> is a persistence entity` | `Bind a record from the service's model and map the entity in the operation.` |

## Review Focus

1. **Malformed request bytes.** A request whose bytes aren't a valid message must yield `INVALID_ARGUMENT` with `ErrorInfo.reason = MALFORMED_REQUEST` and the correlation id, never `UNKNOWN` "Application error processing RPC". Pinned in Task 9: `malformedRequestIsInvalidArgument`.
2. **Context left on a thread after a failing call.** gRPC reuses executor threads; after a call whose operation throws, the next call on the same thread must see no `RequestContext` and no `correlationId` in MDC. Pinned in Task 6: `contextIsClearedAfterFailingCall` (single-thread executor).
3. **Raw caller baggage for Synapse fields.** Metadata `baggage: correlationId=evil` without `x-correlation-id` must give a valid generated id in MDC, the span and the trailer, never `evil`; with `trusted=false` a caller's `traceparent` must not become the parent. Pinned in Task 5: `rawBaggageCorrelationIdNeverReachesMdc`, `untrustedCallStartsANewTrace`.
4. **A permit lost on cancellation.** A client that cancels, or a deadline that expires while the operation runs, must release the permit: with `max-concurrent-calls=1`, 50 cancelled calls, then call 51 is admitted. Pinned in Task 6: `permitIsReleasedWhenTheClientCancels`.
5. **A nullable component on a field without presence.** `@Nullable Integer year` bound to a plain `int32 year` would turn "absent" into `0` silently; startup must fail with the *Nullable without presence* message. Pinned in Task 8: `nullableComponentNeedsPresence`.
